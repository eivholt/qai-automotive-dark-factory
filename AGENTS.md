# Dark factory development

Read [AGENT_MEMORY.md](AGENT_MEMORY.md) for the user's current demo direction, planned modalities and open adapter experiments. The implementation-specific rules below describe the current starter; evolve them with the approved modality work.

- Keep the inspection cell replaceable and consult AGENT_MEMORY.md for the current model-gated automotive sequence and locally supplied assets.
- The imported welding cell retains its legacy visual cycle by default. Explicit -Process uses the independent automotive-process-v1 contract and host Cosmos-Reason2-2B endpoint; never route it through the old battery/parcel bridge. Offline capture and native policy tests are explicitly labeled and cannot establish model accuracy. The procedural scene uses explicit mock inference.
- The spectator camera and fixed sensor are independent. Never send HUD, ground truth, seed, case name, or labels to the model.
- Keep the NIR lossless 448 x 256 grayscale sensor processing and versioned prompt identical across capture, training, evaluation and deployment.
- G means proceed, A means hold/insufficient evidence, and R means anomaly/reject. Transport failures and stale replies hold the simulation.
- Night vision currently means an active-NIR rendering proxy. Unreal visible-spectrum materials are not measured infrared reflectance, and this is not thermal imaging.
- Observer post-process and sensor-preview shaders are display-only. Keep their gain, phosphor palette, grain and lens effects out of the model PNG path. Rebuild generated materials from unreal/Shaders via setup_content.py after shader edits, then run NightVisionSmoke and scripts/verify_night_vision.py.
- The normal visible observer uses dim roof-window spill on view channel 0. Keep it separate from the active-NIR channel 1; indirect and volumetric spill stay disabled. Zero-light NIR smoke/calibration and dataset capture explicitly disable roof light. Native modality screenshots verify both sensor PNGs remain identical with roof light on/off.
- Bright factory is observer mode 3 in the Tab / Xbox Y cycle. Keep fluorescent geometry hidden from fixed scene captures and direct lighting on visible view channel 0, with shared GI/reflection/translucent paths disabled. The headlamp emits only in dim mode; preserve its preference and disable L changes in bright mode. Run WeldingSmoke and scripts/verify_factory_lighting.py after changes to the banks or mode/headlamp interlock.
- Interactive infrared switches affect only the observer. The fixed NIR sensor/illuminator use view-lighting channel 1; the camera-mounted observer illuminator uses channel 2 and observer mask 4, emitting only in NIR mode. Preserve exact fixed-sensor PNG parity when the observer moves or toggles its beam. Keep shared indirect/reflection/volumetric/translucent paths disabled for observer lights. View-lighting channels are separate from primitive lighting channels. Sensor-off mode is only for explicit offline calibration/data.
- Live HUD previews must sample the GPU render target directly. Keep async readback/encoding bounded, tag both preview and pending jobs with episode epoch/capture time, and reject stale pixels before publication. Offline synchronous capture remains the parity reference. Run ReadbackSmoke and scripts/verify_unreal_bridge.py for capture-path changes.
- Thermal rendering uses assigned surface temperatures, emissivity and an 8-14 um apparent-temperature LUT. Keep the fixed thermal sensor linear grayscale at its recorded temperature window; palettes are display-only. Thermal snapshots have a separate contract and must not enter the NIR adapter/bridge. See docs/thermal_rendering.md.
- Thermal shader edits require generated-material rebuilding, ThermalSmoke, scripts/verify_thermal.py, scripts/verify_thermal_fields.py and scripts/verify_thermal_transfer.py. Run the standalone heat solver tests for transport changes. Preserve opaque occlusion, lighting independence, NIR input invariance and async snapshot parity. Manual thermal captures need bAlwaysPersistRenderingState for Unreal blendable materials. Spatial fields use component-local bounds and selected cooling age; working powered heaters are thermal reservoirs; failed heaters are passive. Heat exchange is enabled by default; legacy field regression runs disable it. Preserve motion invariance and keep debug ID masks confined to offline QA.
- Save whole randomization episodes to only one dataset split. Generated images, Unreal content, model weights and purchased assets stay out of Git; retain reproducible source/generation scripts.
- Treat the adjacent qai-physics-reasoning repository and its running model services as reference material. Do not modify its production deployment as part of routine development here.
- Build with the installed UE 5.8 toolchain. Run Python unittest discovery and a rendered Unreal smoke check for changes to capture, model transport or scene state.

- Local welding geometry is regenerated with scripts/assets/prepare_welding_cell.ps1 and unreal/Scripts/import_welding_cell.ps1. Preserve source FBX hashes, per-island assignment conservation, component-local pivots, imported bounds and material links. Keep /assets/, generated Unreal packages and all renders/audits ignored. Run WeldingSmoke after imported scene/motion/camera changes. The rig uses authored production-cycle poses and joint-anchored spline hose surrogates; it is not calibrated industrial kinematics. Maintain shared physical spark state across all views and capture after Chaos/particle updates. Keep the observer headlamp isolated to visible view channel 0. Welding arcs deliberately illuminate visible and NIR; thermal uses explicit particle cooling profiles.
- Imported thermal profiles must remain explicit illustrative surfaces until physical thickness/contact data is authored. Do not apply the procedural solid-box heat solver to whole background material groups or the hollow car body. Never bypass the imported-mode guards to feed the old four-module prompt/labels or training path.

- Robot approach choreography is authored per joint in approach_angles_deg at normalized .20/.56/.80, with unchanged rest and five welding poses. Preserve one-second approach/withdrawal and the default 21-second body cycle with seeded per-robot rest delay 0.2-0.8 s, pre-weld dwell 0.5-2 s and full 7.5-second welds. The 16-cycle schedule repeats deterministically; carriage departure must follow all withdrawals by at least 0.5 s. The synchronized 18-second schedule is an explicitly selected legacy QA fixture only. Emission and tool/body heat use each robot's local weld clock; retain stable emitter indices in sparse active subsets. Update using prepare_welding_cell.py --approach-only, then run WeldingSmoke and scripts/verify_robot_choreography.py and review the intermediate rendered poses. Sampled point/vertex clearance is not full swept-volume certification.

- Robot motor/casting heat follows the authored joint trajectory and a continuous simulation clock. Preserve deterministic seeking, residual warmth across cycle wraps, cooling at rest, pause behavior and mesh-local gradients. Ordinary motor temperatures affect thermal views only. Keep tools/car welds independent and imported bulk exchange disabled. After changes, run WeldingSmoke and scripts/verify_motor_heat.py alongside relevant existing welding checks; preserve fixed-NIR parity. See docs/robot_motor_heat.md.

- Cinematic welding expulsion uses staggered burst/fountain/fallout phases with physical spark collisions and a bounded optical smoke pool. Keep the shared particle state paused during camera comparisons; smoke affects visible/NIR only and must not become an opaque thermal surface. Regenerate the smoke and imported fixed-NIR materials with setup_welding_smoke.py/setup_welding_nir.py after their shader edits. The imported NIR GPU grayscale pass runs after tonemapping with fixed capture sequences; leave procedural training capture separate. Run WeldingSmoke and verify_welding_effects.py plus production/cooling regressions, and inspect actual rendered phase/smoke images. These effects are exaggerated visual proxies, not calibrated weld-quality labels.

- Four IQ9 appearance props attach to robot upper arms with stable local transforms. Preserve private photographic asset provenance, decorative LED animation and the bounded 28-surface thermal addition; these are visual props, not live EVK telemetry. Keep HUD FPS based on smoothed real game-frame intervals, updating while cell motion is paused and excluded from fixed sensor PNGs. Pin decorative LED time before frozen QA pose changes and retain stable light proxies during sensor comparisons. Run WeldingSmoke and scripts/verify_robot_expansion.py for schedule/prop/observer-NIR/FPS changes, alongside legacy capture and cooling checks. Inspect prop closeups for visibility and exposure; nonblank-image checks alone do not establish a usable prop render.

- Imported realism additions are enabled in interactive mode and `-RealismSmoke`, but hidden/disabled in legacy `-WeldingSmoke`. Preserve this fixture distinction. Environment details use bounded ISM batches and no tick; mechanisms follow the cell clock with fitted source-panel contacts and geometric photoeye occupancy; legacy indicators/HUD must never imply model acceptance; process-mode indicators reflect only the process controller status. Keep six synthesized sources bounded, callback-owned DSP state free of UObject access, and pause/mute silent. Weld-witness material generation must preserve original color/roughness and heat branches, replay idempotently, leave shared defaults disabled, reset each new body and not alter thermal temperatures. B / Xbox X moves only the observer; manual flight cancels transitions. Run RealismSmoke plus scripts/verify_realism.py after changing these elements and visually review the affected views. Use the current thermal-preview bounds in screenshot ROIs. See docs/realism_additions.md for research, resource budgets and validation.

- Cabinet LCD/buttons use the existing 13-island SM_Background_robots_screen material only. Preserve source texture/geometry and runtime restoration, simulation-clock GPU gauges, pause/seek determinism, source red/green lens colors, one bounded spill light and unchanged thermal profile IDs. Keep brightness separate from thermal temperature. Regenerate setup_control_cabinet.py after ControlCabinet.usf edits and run CabinetSmoke plus scripts/verify_control_cabinet.py; visually inspect actual text orientation, NIR glare and every lens. Placement comes from scripts/assets/prepare_control_cabinets.py and remains private. Legacy fixture appearance stays disabled.

- Automotive process mode has two fixed opposite-side NIR cameras and one physical R4 thermal camera aimed at three inspection areas. R4 must never weld; it deploys only during adhesive/weld-cooling gates and returns to authored rest elsewhere. Keep its 0.8-second transition on the pausable process clock and wait for the calibrated active endpoint before thermal capture. Only two consecutive fresh model G replies may advance a gate; door R returns the body, thermal R waits, A/errors/stale replies hold. Pause invalidates pending captures and replies. Keep the simulation heat clock advancing while motion poses wait; no schedule-only motor heating during holds. Preserve legacy motion/heat branches.
- Process model PNGs exclude HUD, cabinet display and gate lamps. Never send source fault state, temperatures, labels, case/seed metadata or prior decisions to Reason2. Output datasets are offline, labeled and private, with whole-body episode splits. Review camera coverage and non-clipping before measuring model accuracy. Small in-scene adapter experiments are development results, not real-camera validation.
- Rebuild and render process capture after changing door geometry, camera aiming/exposure or process state; verify policy with ProcessPolicySmoke and actual inference separately with ProcessSmoke. Preserve the 1/3 live door-fault probability, four authored supplemental door inserts, cleanup on return/departure and continuous adhesive/weld cooldown. Unsupported edits to the frozen sensor/window/threshold/consensus contract must fail initialization; changing supported model policy requires matching server/client policy echoes.

- Portal curtain physics binds its original joint frames once after the first physics step; validate live constraint handles, not just component count. Explicit pause/QA owns startup. It uses broad suspension swing and limited relative strip bends. Pause/resume preserves velocities and original body-local anchors; only explicit reset discards momentum. After curtain/portal/collider changes, run the separate rendered CurtainSmoke and scripts/verify_curtains.py plus WeldingSmoke. Inspect entry, return and exit contact/settling images; finite state and anchor error alone do not rule out back-folding. CurtainSmoke is a physics fixture with process door geometry and no model requests, not classification evidence.
