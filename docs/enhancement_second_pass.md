# Equipment, thermal reflections and inspection evidence

The second pass advances roadmap items 2, 4, 5, 9 and 10. Enable the equipment,
motion, replay retention and observer thermal reflection additions with
`-Enhancements`. The existing four live gates and their thresholds are unchanged.

## Inspection replay

F5 switches the right HUD panel between live GPU previews and historical request
receipts. Page Up/Down browse the last eight requests. `-InspectionReplay` opens
the panel initially. Each receipt retains the three actual submitted PNGs,
request/body/stage identity, returned G/A/R, conditional label score, label mass,
HTTP elapsed time and actual resulting controller action. Thermal replay images
are deliberately grayscale, matching model input. A conditional label score is
not a calibrated probability of correctness.

Replay does not pause the simulation; Space / Xbox View pauses and resumes it.
The project removes Unreal's inherited F5 shader-complexity and Page Up/Down
debug-target bindings so these keys reach the replay controls. Restart the demo
after updating input configuration. In an older running instance, F3 restores
the normal lit view if F5 activated the red/green shader-complexity overlay.

The textures are decoded once from the existing encoded request, bounded to 24
448×256 RGBA textures (about 10.5 MiB plus object overhead). Live previews still
sample GPU render targets. Historical images never re-enter inference. Cancelled,
stale and mismatched requests cannot appear as accepted receipts; pause invalidates
pending requests without erasing completed history. Normal interactive operation
does not write replay images to disk. Replay annotations are HUD-only.

## Hoses and seating

`scripts/assets/prepare_hose_sleeve.py` generates a ribbed sleeve with Blender's
background Python API; `setup_hose_sleeve.py` imports its private FBX. Twenty
existing spline sections use the new mesh, with 24 collars at joint anchors.
No new heat sources are added: process collars share the adjacent hose profile.
The optional asset has a cylinder fallback. Legacy fixtures without enhancements
retain their previous geometry.

Prepare the optional assets on the local machine before rebuilding content:

```powershell
& 'C:/Program Files/Blender Foundation/Blender 5.2/blender.exe' --background --factory-startup --python scripts/assets/prepare_hose_sleeve.py
wsl.exe -e /home/eivho/cosmos-reason2-finetune/.venv/bin/python scripts/assets/prepare_panel_lowering.py
.\unreal\Scripts\build.ps1
```

During placement/retraction, Hermite tangent adjustments add less than 1 cm of
authored hose sag/sway while preserving anchor positions. They use process time,
so pause and deterministic seeks remain stable. This is not cable dynamics.

The four gripper pads extend from 3 to 3.8 cm when unloaded and compress/bulge
under pickup and final seating load. A 0.6-degree panel tilt during final lowering
provides progressive contact through actual R3 joints. The panel stays attached
to its gripper, and settled panel, weld and inspection poses remain unchanged.
`prepare_panel_lowering.py` fits 51 actual joint poses, compensating for the long
gripper's sideways sweep. The private descriptor is tied to the source authoring
hash and is regenerated by `prepare_welding_cell.ps1`; missing optional data uses
the previous lowering path. This avoids a per-frame inverse-kinematics solver.
These are compliant-looking authored movements, not deformable-body contact
simulation. Additional bundled wiring, squeeze-out and subtle uneven-gap fault
cases remain future work; the established large seating-fault cases are retained.

## GPU thermal reflections

The observer thermal material traces one screen-space reflection ray with at
most 24 depth samples over 3 m. It stops at the first visible opaque depth
crossing, rejects large disocclusion jumps and falls back to ambient on misses.
Only registered visible surfaces supply reflected heat. The shared direct-surface
evaluator includes the existing nonuniform fields and local tool/weld/contact
temperatures; it does not read visible RGB lighting.

Reflectance uses `1 - emissivity`, stored in previously unused LUT row 15 alpha.
The LUT remains 256×70 / 280 KiB. Reflected radiance is mixed using a closed-form
11 µm Planck approximation. The established direct-temperature calculation still
uses its 8–14 µm apparent-temperature fits. This new reflection path is a display
experiment, not calibrated band-integrated thermography, a roughness-aware BRDF,
or a ray-traced solution for off-screen/hidden geometry. Screen-space misses and
edge fading are expected. It adds no scene capture or CPU pixel processing; a
GPU timing benchmark has not yet been established.

`-NoThermalReflections` disables the observer effect. All model/fixed materials
explicitly bind its enable parameter to zero. Source temperature, heat transfer
and model grayscale encoding remain independent of this display setting.

The design follows [FLIR's emissivity and reflected-temperature explanation](https://www.flir.com/discover/professional-tools/how-does-emissivity-affect-thermal-imaging/)
and Unreal 5.8's installed `ScreenSpaceShadowRayCast.ush` projection conventions.
Low-emissivity surfaces can reflect nearby objects; a thermal image should not be
interpreted as a direct material-temperature map without that distinction.

`-DFThermalSmoke -DFThermalReflectionSmoke` adds a dedicated reflective-plate/hot
object fixture. It checks an observable reflection, no reflected warmth when the
source is hidden, and a uniform receiver when emissivity is one. Its temporary
objects/profile changes are removed before the remaining thermal smoke checks.

## Sealant coverage: offline only

The separate `automotive-sealant-coverage-study-v1` contract asks Reason2 to inspect
continuity, width and placement before the panel hides the sealant. Capture uses
the physical R4 right/left/right contact poses, active NIR and the existing three
lossless 448×256 grayscale images. No camera labels, source cases or temperatures
are included in the model message.

```powershell
.\unreal\Scripts\run.ps1 -Scene welding -ProcessCapture -SealantCoverageCapture -ProcessEpisodes 4 -ProcessDatasetSeed 811 -Enhancements -NoInference -Output artifacts/my-coverage-study
```

Each whole episode contains nominal coverage, a gap on either run, severe
thinning, lateral displacement, either missing run and an occluded example.
Faults modify actual rendered geometry. Entire episodes stay in one split.
The capture flag is rejected outside offline capture; the production contract
loader rejects this study contract. Its source labels are provisional until
image observability has been reviewed.

`scripts/model/evaluate_sealant_coverage.py` runs the local base model directly on
training-development rows only. It uses the existing full-vocabulary next-token
scoring implementation, without modifying the live service or loading a current
panel adapter under the new prompt. Example on the prepared WSL environment:

```bash
PYTHONPATH=src /home/eivho/cosmos-reason2-finetune/.venv/bin/python scripts/model/evaluate_sealant_coverage.py \
  --manifest artifacts/my-coverage-study/manifest.jsonl \
  --model /home/eivho/cosmos-reason2-finetune/base/Cosmos-Reason2-2B \
  --output artifacts/my-coverage-study/base-development.json
```

The first study captured four episodes / 32 triplets / 96 PNGs. Only the two
training episodes (16 triplets) were evaluated. Median warm request time was
60.0 ms; source-label agreement was 1/16, with seven false G responses against
the provisional source labels. Thin sealant and wide views need further visual
coverage work. These results rule out deploying this base-model prompt as a gate.
They are not held-out accuracy measurements. No new adapter has been trained,
and targeted reapplication is not yet connected to the live controller.

Next steps are to improve inspectable bead coverage, review labels, train an
explicitly compatible coverage adapter, evaluate untouched episodes, and then
add a fresh-consensus live gate and bounded targeted reapplication. Existing
thermal/presence/seating adapters must not silently stand in for that new task.

## Validation

The completed pass passed the UE 5.8 build, 124 Python tests, 104 native policy
checks, 2,012 graphics isolation checks, rendered motion, 56 mounting-frame checks,
3,271 pinch checks, thermal/field/transfer fixtures and all nine legacy welding
suites. The final actual-host sequence completed assembly/preassembled/assembly
with 27 requests and six thermal acceptance audits. R4 telemetry passed 5,248
checks, curtains 27 checks, and the replay retained eight complete three-image
receipts. Equipment, lowering, reflection and replay screenshots were reviewed.
These results validate local integration, not new held-out model accuracy.
