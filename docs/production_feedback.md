# Production feedback

This implements elements **7 (spatial factory soundscape)** and **8 (production-status strip)** of the requested factory-detail pass. Both follow the imported welding simulation. They do not indicate inspection quality, live IQ9 telemetry or model decisions.

## 7. Spatial factory soundscape

Factory machinery has multiple noise sources, and their physical mechanisms differ. HSE's engineering examples include vibration and conveyor-related noise; its noise guidance also describes sound from rotating fan blades. These support distinct drive and extractor layers rather than one undifferentiated room recording. The chosen pitches, levels and weld crackle remain authored demonstration sounds, not measurements or an exposure model. [HSE: noise in engineering](https://www.hse.gov.uk/engineering/noise.htm), [HSE: controlling noise at work](https://www.hse.gov.uk/pubns/priced/l108.pdf).

Six mono sources are created once: four robot servo/weld sources, one carriage drive, and one overhead extractor. Each robot source follows its tool-roll joint. The carriage source follows the actual body bounds. The extractor sits above the station. Unreal's spatial panning and distance attenuation place the sounds relative to the observer, with a 250 cm inner radius and 4,500 cm falloff. No acoustic ray tracing, occlusion queries or room-reverberation simulation is added. [Epic: sound attenuation](https://dev.epicgames.com/documentation/unreal-engine/sound-attenuation-in-unreal-engine).

The servo envelope follows each robot's actual approach/withdrawal interval and authored motion knots, with a quieter precision-tracking layer during welding. Weld crackle uses the same robot-local 1.05 s burst/fountain/fallout pulse schedule as the cinematic sparks, including the explicitly selected legacy stagger only in the old QA fixture. The carriage drive follows the arrival/departure easing and is silent while the carriage is stationary. Extractor hum continues through normal running dwells. These cues are synchronized procedural approximations; they are not recorded resistance-welding acoustics or fault alarms.

**M** mutes/unmutes sound. Scene pause silences all six layers while preserving the mute preference. Disable, mute and pause use an 8 ms gain-smoothing time constant to avoid abrupt clicks; output becomes exactly zero after the release settles. Camera/observer mode changes do not change the sound state. Audio never enters a model image or thermal profile.

`DarkFactorySoundscape.h/.cpp` uses the current `ISoundGenerator` path behind six `USynthComponent` sources. Unreal's local UE 5.8 header recommends separate generator objects over generating audio on UObjects. The audio callback owns its oscillator/filter/seed state and reads atomic scalar controls; it performs no allocation, locking, file access or UObject traversal. Output is bounded to 0.11 peak per source. A fixed six-source pool avoids event-spawned audio growth. This is a resource bound, not a measured frame-rate result. [Epic: audio engine overview](https://dev.epicgames.com/documentation/en-us/unreal-engine/audio-engine-overview-in-unreal-engine).

Integration is `Initialize(Cell)`, then actor tick or explicit `UpdateFromCell()` after offline seeks. Root controls `SetEnabled`, `SetMuted` and `IsMuted`. The AudioMixer module is required. `BuildMetadata()` records the source clocks, six positions/envelopes, spatial settings, output gates, finite-state flag, generated samples and observed buffer RMS/peak. A running source alone does not prove that a sound device emitted audio.

`BuildDSPSelfCheck()` renders every generator, checks nonzero active RMS, bounded finite samples, deterministic repeated PCM and exact silence after the mute release. `SaveOfflinePreviewForQA(WavPath)` writes a deterministic 48 kHz, 16-bit mono first-cycle audition from the same kernels and real schedule envelopes without moving the scene. Its JSON records peak/RMS and the self-check. This file verifies DSP and synchronization; it excludes Unreal's live spatial mixer, listener attenuation and sound device. A separate live listening check is needed for spatial placement and comfortable balance.

## 8. Production-status strip

A manufacturing HMI should expose actual controller state. NIST describes state reports and status monitoring as core HMI functions. The demo therefore reads the cell clock and per-robot timing directly rather than maintaining an independent animation timer or inventing production outcomes. [NIST: software models for the HMI/controller connection](https://tsapps.nist.gov/publication/get_pdf.cfm?pub_id=820652).

The imported observer HUD shows the current body sequence, bodies that have fully exited, elapsed/total cycle time, a progress bar, and four text-labeled robot phases: Rest, Approach, At contact, Welding, Withdraw and Parked. `PAUSED` is explicit and the progress freezes with machine motion. Body counts describe the simulated sequence, including deterministic seeks; they are not good-part counts, accepted inspections or a persistent production database. Phase colors supplement text.

The strip occupies the upper space between the observer/FPS panel and fixed sensor previews. Small windows place it on a second top row. Existing thermal legends, palettes, FPS and sensor panels stay intact. Bottom controls include **B / Xbox X: viewpoint** and **M: sound**. No new camera capture, texture upload or sensor readback is required. `BuildProductionStatusMetadata()` exposes the same source values for offline checks.

The native UE 5.8 build and rendered feature QA pass. All six DSP self-checks report bounded finite active output, deterministic repeated PCM and exact settled mute silence. The 21-second offline audition peaks at 0.1627 with RMS 0.0238. A separate independent HUD report validates all 12 sampled clocks/body counts/progress values and 48 robot-phase labels; frozen observer changes preserve both fixed sensor PNGs exactly. The HUD was visually reviewed at 1600 x 900 and 1280 x 720, including production status, all three previews, thermal legends and controls. Live-device spatial placement and listening balance remain unverified by these offline checks. See [combined validation](realism_additions.md#validation-2026-09-13).
